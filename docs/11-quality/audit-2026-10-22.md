# Auditoría de calidad y consistencia — 2026-10-22

## Alcance y método

Se revisaron los 92 documentos Markdown existentes contra el SRS, documento de pruebas y despliegue de Drive, y contra las ramas auditadas de web, backend, base de datos e IA. La revisión fue estática: no ejecutó clientes, API, migraciones, modelo ni infraestructura.

## Hallazgos corregidos

| Severidad | Hallazgo | Corrección aplicada |
| --- | --- | --- |
| Alta | La integración cliente–IA se describía como si no hubiera contrato implementado. | Se documentó el WebSocket `/ws/recognize`, envío de frames y mensajes de predicción en web y móvil; se mantiene pendiente la ejecución real. |
| Alta | El diccionario mezclaba tablas históricas con el esquema final. | Se reflejó que `sessions`, catálogos `signs`/`translation_signs`/`audio_files` se eliminan; permisos se restauran y `files` se retira. |
| Media | La documentación de permisos móvil confundía permiso funcional de API con permiso del sistema. | Se distingue `CAMERA` nativo de preferencias `camera`/`audio`; no se afirma permiso de audio de SO. |
| Media | Los puertos de IA no eran coherentes. | Se registró la discrepancia: móvil usa `8001` por defecto, IA auditada `8000`; se exige configuración explícita. |
| Media | Despliegue se marcaba como inexistente pese a evidencia documental de Drive. | Se incorporó el despliegue documentado con VPS/Nginx/HTTPS/WSS, separándolo de verificación independiente. |
| Baja | API no mostraba el contrato de entrada confirmado. | Se añadieron DTO/campos, multipart y reglas públicas de `SecurityConfig`. |
